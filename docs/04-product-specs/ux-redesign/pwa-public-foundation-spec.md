## Worker privacy and lifecycle
Only fixed same-origin public resources are precached: offline.html, stylesheet/theme helper, pinned public tokens, generic platform icons (Apple icon is metadata-only, not precached) and licensed Cairo400/600. No runtime /_next/static caching in this foundation; the original broader static-assets requirement remains an OPEN original-plan design/acceptance item, not silently removed from final success. No query/fragment/encoded/Authorization/RSC/Range request intercepted for public assets. Private pages/data/RSC/API/exports/PDF/signedURLs/nonGET and Server Actions pass through without respondWith. Protected callback/export/API navigation also passes through. Only same-origin GET navigation may fetch the ORIGINAL Request once and substitute the public fallback on network rejection; HTTP errors/redirects remain their authoritative response. No body inspection, account cache, queue, replay, retries, push or background sync.
Fixed install uses native Cache.addAll with cache:reload, credentials:omit and per-asset SHA256 integrity. Successful public byte identity is pinned; rewritten/private responses cannot match. Install rejection is nonblocking and atomic under native Cache semantics, never made successful by dropping an asset. One reserved bp-public-v1 cache; activation prunes only outdated keys inside this cache. No other cache/storage deletion or account/tenant-specific values. Missing/unreadable cache returns truthful503 no-store plain fallback. No fake receipt or resolved attempt. Integrity digests must be regenerated and verified whenever public bytes change.
No skipWaiting/clients.claim/forced refresh or update prompt: existing open business forms retain native worker lifecycle. Registration only production+supported securecontext; failure stays nonblocking. No worker registration in dev/tests merely from importing code. sw.js response application/javascript, no-cache/no-store/must-revalidate and same-origin CSP; no wider Service-Worker-Allowed grant.
First page is not controlled: qualify only a subsequent navigation after native activation. Retirement payload (preserved with evidence, never applied to a running environment here) registers no fetch handler, deletes only bp-public-v1 and unregisters its own registration on native activation. Replacing a released sw.js requires separately authorised release; no skipWaiting/forced refresh.
