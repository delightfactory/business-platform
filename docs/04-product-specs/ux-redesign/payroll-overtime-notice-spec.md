## Evidence that prevents an unsafe shortcut

The existing public.attendance_payroll_input_projection(uuid,date,date,date,text,uuid,integer) returns tenant-wide pages of at most100 approved current work facts, bounded to31 inclusive dates. Item metadata includes employment_id, employee_code and instance_id, but no employer binding. Root payroll_run_workspace uses p_limit1, with candidate employee partitions that may be stale or incomplete; these cannot establish all attendance employment ownership. The projection has independent attendance permission guards, and its latest classified-facts patch adds leave_covered and reconciliation metadata. Root payroll authority does not imply attendance authority. Do not sum a first page, assume that the first payroll employee is the entire employer, infer zero from a missing/error/denied read, or label the tenant total as an employer total.

## Intended actor and complete task

An existing payroll reader who also has the existing source attendance read authority selects employer/period, sees the source's unclassified overtime warning, opens the existing attendance instance, and uses its existing permitted classification task. Returning to payroll and recalculating remains explicit where currently required. Payroll-only readers see a truthful unavailable-source explanation, not attendance details or a guessed classification action. No new input, financial amount, automatic classification, blocker, payment decision or write is introduced.

## Proposed minimum read contract

Use a small protected read accessor over cross-role N+1 lookups or changing the legacy projection signature/DTO. The final signature and authorization are specified in the controlling co-design corrections below; this accessor is not deployed.

Validate current authenticated payroll_run_access and the same current source attendance permissions admitted by the original projection, with tenant/employer/period binding from payroll.periods and the employment head's employer_entity_id. Never infer authority from a source owner label or employee manager. Scope/active-employer validation mirrors payroll_run_workspace; another tenant's period/cursor or malformed limit must fail closed. Reuse existing entitlement/read-history semantics; do not silently broaden permission or disable historical reads. Do not add grants to anon/service_role, default privileges or production.

In one consistent source read, reuse the projection's actual relational eligibility: latest attendance fact of an approved work instance in this period, source outcome worked/absence/leave_covered, overtime candidates tied to that exact fact, no classification, and no rejected decision. Bind employer via tenant+employment_id to people.employments.employer_entity_id. Return only scoped period identity, confirmed totals and a bounded list/cursor sufficient to open original instances: instance_id, operational_date, employee_code, unclassified count/minutes. Do not return reasons, location/biometric payload, leave details, payroll money, raw fact JSON or personal account data. Decide in co-design whether full totals are justified; never describe a paginated sample as a full total. Existing classification reconciliation/currentness must remain visible when consequential; this read cannot certify payroll readiness or consumption.

The root panel is informational/nonblocking and uses existing notice/secondary tokens. It must distinguish available nonzero, available empty, denied, disabled source, failed/partial/malformed and stale/reconciliation-required source. Do not hold the existing payroll primary hostage to this supplementary read. Never expose source errors/IDs as a user-facing substitute for a recovery action. Existing financial authority/revision/approval/finalization/source checks stay authoritative. Final/superseded payroll history must not inherit a current warning as a statement about the protected historical output; candidate/no-run placement and context are part of co-design.
