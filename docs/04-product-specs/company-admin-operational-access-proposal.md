# استخدام مسؤول الشركة للموارد البشرية بنفس الحساب

الحالة: معتمد بقرار المالك «موافق على منح الصلاحيات المطلوبة»،10أكتوبر2026. الاعتماد يخص الاختيار الصريح لمجموعات العمل الموجودة، دون منح تلقائي. التنفيذ والتحقق المحلي قيد الإكمال، ولا نشر أو دمج. المرجع: هدف بدء الشركة دون مساعدة برمجية، وحدود صلاحيات المؤسسة وقوالب الأدوار الثابتة.

الدليل الحالي: إنشاء شركة جديدة من الدعوة والبريد المحلي وواجهة القبول نجح علىadfcc60. دور المسؤول الأول يحتوي صلاحيات إدارة الشركة والأعضاء والجهات والفروع فقط. لم تظهر الموظفون والرواتب. الدالة الحالية `set_tenant_member_people_bundles` ترفض استهداف أي مسؤول محمي بـ`tenant_people_role_bundle_admin_protected`؛ الواجهة تخفي تعديل المجموعات له. لا محاولة لتجاوز هذا الرفض.

الخيار المقترح: يستطيع مسؤول يملك صلاحية إدارة الأعضاء اختيار مجموعات العمل الموجودة لحساب المسؤول المحمي، بما فيها حسابه، من نفس شاشة المستخدمين. لا تُمنح تلقائيًا عند إنشاء شركة ولا بمجرد امتلاك دور المسؤول. لا يُنشأ دور شامل جديد. تُعرض آثار الصلاحيات بوضوح، خصوصًا عرض الأجر وتعديله وتجهيز الرواتب واعتمادها.

تبقى صلاحية إدارة الشركة ودورها المحمي خارج قائمة مجموعات العمل وخارج عمليات إضافتها وسحبها. لا تعديل لقالب الدور أو صلاحيات عضو موجود بصمت. يبقى التحقق من الشركة والحساب النشط والصلاحية، وقفل التزامن والتدقيق، وحماية آخر مسؤول قابل للاسترداد، وحدود الخدمة، والقيود الأصلية لحساب الرواتب واعتمادها وتصحيحها. لا صلاحيات تشغيل منصة أو وصول لشركة أخرى.

البديل الحالي: يدعو المسؤول حساب عضو مستقل ويمنحه مجموعات العمل. يحافظ على الفصل الحالي، لكنه يفرض حسابًا إضافيًا حتى عندما يدير نفس الشخص الشركة والموارد البشرية. تفعيل خدمة الشركة بواسطة مشغّل المنصة يبقى منفصلًا في الخيارين.

القرار المعتمد: السماح باختيار مجموعات العمل صراحةً لحساب مسؤول الشركة بدل إلزام حساب عضو مستقل. التغيير يقتصر على القيد المحدد في الخادم وإتاحة المحرر الحالي في الواجهة، مع قبول مركز لعدم المساس بدور المسؤول المحمي. لا نشر أو دمج ضمن الاعتماد.

مراجعة مستقلة مكتملة: Claude Code الرسمي Opus5.5 Medium أيد إزالة قيد استهداف المسؤول من المسار الموجود وإظهار محرر المجموعات الحالي، بدل إنشاء دور أو شاشة جديدة. التحقق الموجود قبل الحذف يرفض أي دور محمي يصطدم بمفتاح الكتالوج؛ صفحة المستخدمين نفسها تتطلب إدارة الأعضاء؛ §21 من مواصفة الرواتب يسمح لشخص واحد بعدة صلاحيات في الشركة الصغيرة، والإجراءات الحساسة تبقى صريحة ومدققة. لا فصل إجباري جديد ولا تعديل مالي. بعد استعادة Docker طُبقت migration على قاعدة QA المملوكة، ونجح قبول SQL المركز للمنح والتكرار والسحب وحماية تعيين المسؤول والتدقيق ورفض الوصول غير المصرح. نجح المنح والسحب وإعادة المنح من الواجهة مع تحديث التنقل دون إعادة تحميل يدوي. lint وtypecheck ناجحان؛ هذا قبول للتغيير المحدد وليس إغلاقًا لرحلة الموارد البشرية كاملة.
