# R7 source summary and readiness: co-design verdict (spec on 463a16b)

**I approve, with three spec corrections and the guards below.** I read the spec, the root summary type, the root summary and issue lines (`page.tsx:18–21`, `101–110`), and drew on my earlier reads of the inputs prerequisites and the runs summary.

## Spec corrections (precise)

1. **Show net only for recognized candidate statuses.**
   - **Why:** on root, `candidate` is true for *any* run status other than cancelled, locked or superseded, which includes unknown statuses (`page.tsx`, the definition of `candidate`).
   - **Rule:** show net only when **all** of these hold:
     - the run status is one of `draft`, `review` or `approved`;
     - `summary.financially_qualified === true`;
     - there are no stale reasons;
     - `summary.net != null`.
   - **Otherwise:**
     - **unknown status:** a neutral explanation;
     - **stale:** "أعد الحساب لعرض الصافي";
     - **unqualified or missing:** "يظهر بعد اكتمال التأهيل المالي".

2. **Mirror the runs gross semantics exactly.** Runs shows **`known_gross`** in both cases and changes only the label with `gross_complete`: "إجمالي الاستحقاقات التشغيلية" when complete, "الاستحقاقات المعروفة من المدخلات التي أمكن حسابها" otherwise (`runs/page.tsx` summary). Root must do the same. Never show `summary.gross`, which can be null when incomplete. A missing flag keeps the "known" wording.

3. **Label stale values honestly.** Gross and deductions stay visible when the source is stale, so add the runs wording "القيم محفوظة من الحساب السابق" (or a near equivalent) next to them, alongside the existing recalculate instruction.
