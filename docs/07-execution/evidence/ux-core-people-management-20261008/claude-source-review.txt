# Core R4 management: source/spec checkpoint verdict

**Verdict: no must-fix items in the source I read.** It matches the spec's source-level claims. This is a source checkpoint only, not a passed qualification. Both visual verdicts are **NOT VISUALLY VERIFIED**, and full R4 stays open.

## What the source supports

**Import (`import/page.tsx:29-34`)**
- The template download and the next-step sentence are always visible.
- The exact file format is inside a native `<details>` element. The literal values (`YYYY-MM-DD`, `monthly`/`daily`, `true`/`false`) are wrapped in `<bdi>`, which keeps left-to-right text correct inside Arabic.
- There's no step indicator and no claim about past import attempts.
- `WorkforceImportForm` is only mounted here. The permission gate (all five access flags) and `Unavailable` look intact.

**Organization (`organization/page.tsx`)**
- An invalid query or page still skips the catalog RPC and shows the existing error (`:33`, `:64-65`).
- Retry uses `listingHref(kind, rawQuery, page)`, so it keeps the current valid kind, query and page (`:68`).
- The cards are a flat list of 3/2/1 columns (`people-management.module.css:1-18`). They show the same fields: name, status, code, parent or department, and the "effectively inactive" note.
- Edit and Add links are still gated on `can_manage_org`. Paging is unchanged, and editing still happens on a separate page.

**Policies (`work-policies/page.tsx`, `PolicyTask.tsx`)**
- The create editor is wrapped in a native `<details>`. It renders before the catalog, which stays visible without the long form. The editor stays mounted, so typed values survive collapsing.
- The pending guard works:
  - `WorkPolicyEditor.tsx:70` sets `aria-busy={pending}` on the `<form>`, which is exactly what `PolicyTask.tsx` looks for.
  - Summary clicks are blocked while that form is busy. Keyboard activation also fires a click, so it is covered too.
  - `onToggle` reopens the disclosure if it closes while busy.
- A save failure comes back through `useActionState` and shows inside the still-open form (`:192`). Only success redirects with `state=saved`.
- The per-policy revision editor uses the same `PolicyTask` wrapper.
- The activate/deactivate form sends the same three hidden fields (`tenantId`, `policyId`, `active`) and now uses `SubmitButton`, which disables the button while pending.
- The "service not configured" state has a back link (`:17`).
- The feedback toast messages are unchanged, and nothing turns a list load or an error into a success message.

With an empty catalog, a creator sees the collapsed create disclosure above "no templates yet". It is discoverable, but not yet confirmed visually.
