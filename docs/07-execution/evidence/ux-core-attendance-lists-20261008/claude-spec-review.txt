## 3. Table/card semantics and accessibility risks
- **One markup:** use a native `<table>` with a `<caption>` (or `aria-labelledby` pointing at the title and date) and `<th scope="col">`. On mobile, CSS that changes `display` on `table/tr/td` makes Chromium and WebKit drop table semantics. You must either add explicit `role="table|rowgroup|row|columnheader|cell"` or confirm with an accessibility-tree check.
- **Mobile labels:** put real per-cell label spans in the markup (`aria-hidden` while header association holds). Don't use CSS `::before` `data-label`, which isn't reliably announced.
- **Messages:** exception and overtime messages go in a notes cell as text. Don't color-code them only, and don't make the whole row a link.
- **Repeated link names:** "فتح السجل" appears on every row. A table gives row context; on cards it's ambiguous. Linking it to the name cell with `aria-describedby` is cheap, but only if you count it as necessary. Otherwise record it as open.
- **DOM order must equal visual order in RTL**, with no `order:` reordering of the toolbar links.
