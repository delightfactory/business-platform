## Source review

**Races I checked and found sound:**
- **Typing over an older result:** if the user keeps typing after a submit, the older result doesn't overwrite the newer text (`DirectorySearch.tsx:45-46`). If an older result ever rendered after a newer submit, it would overwrite the field. Next drops stale navigations, and your fixture saw "latest replaces slow result", so this is fine.
- **Back/forward:** going back or forward cancels the pending debounce, clears the remembered submit, then restores the field from the URL (`:50-55`). When the new page props arrive they set the same value.
- **IME:** no auto-search while composing (`:22`, `:75-76`), and submit is blocked while composing (`:66-68`).
- **No-op searches:** same query on page 1 doesn't auto-submit (`:23`). Explicit same-query retry still navigates and shows pending, and nothing gets re-synced.
- **Cleanup:** timers are cleared on unmount (`:58`).
- **Auth and data:** the RPC call, the 100-character query check, page bounds 1–1000, and permission flags in `page.tsx` are unchanged. Search always targets the fixed tenant directory path from the server.
- **Retry link:** keeps the current query and page (`page.tsx:61`). The `invalidPage ? 1 :` there can never be true in that branch; it's harmless.
- **Pending message:** it says the list on screen is from the last finished search, which is accurate. It doesn't claim the list matches the new text.

**Should-fix (not blocking):**
1. **Button label shifts the layout.** During a search the button changes from "بحث" to "جارٍ البحث…" and the input gets narrower while the user is typing (visible in `search-pending-390.jpg`). Fix: give the button a fixed width, or keep the label the same and let the status line carry the pending message.
2. **Search box resets paging too easily.** On page 2 or later, an edit that trims back to the current query (e.g. a trailing space, or typing then deleting) still auto-submits and drops to page 1. That's because of the `page === 1` condition at `:23`. Fix: skip the auto-search whenever the trimmed text equals the current query.
3. **Two small gaps:**
   - The fresh-page typing check at `:36` compares untrimmed text, so typing only whitespace before hydration triggers a pointless search.
   - `page.tsx:56` shows "نتائج البحث عن:" for a query over 100 characters, even though no search ran. It should only show when the query is valid.

**Still-open gates, not new defects:**
- Native GET with JS disabled.
- Real IME hardware. Safari fires compositionend before the Enter keydown, so Enter would submit the committed text. That's acceptable.
- Real project auth, Supabase and permissions; the fixture can't prove these.
- Full directory, reference-design match, roles, build and lint.
- D16 is deferred; D2, D3 and D8 are pending.
