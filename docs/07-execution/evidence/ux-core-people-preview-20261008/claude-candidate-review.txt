## Must-fix

1. **`[employeeId]/preview/route.ts:20` can show "signed out" when the auth service just failed.** `getUser()` returns an `error` with `user: null` on network failures and server (5xx) errors too. The route treats every `authError` as `signed-out`, so the sheet tells the user to sign in when the real problem was the provider. That's a misleading status.
   - Fix: return `signed-out` only when there's no session (no error, or `AuthSessionMissingError`), or when the auth API rejects the token with a 4xx.
   - Retryable fetch errors and 5xx should return `unavailable`, which offers retry plus the full profile.
   - Add one route test for each branch.
2. **`EmployeePreview.tsx:94`: the label `سيبدأ قريبًا` ("starts soon") claims more than the data says.** The RPC only says the start date is in the future, which could be months away. Use a neutral label such as `مجدول` ("scheduled"). The start date is already shown under التوظيف (Employment).
