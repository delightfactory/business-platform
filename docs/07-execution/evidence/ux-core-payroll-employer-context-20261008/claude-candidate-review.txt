## Must-fix: the same-employer submit drops the corrected-advance link on advances

- **Where:** in `employer-context.ts:10`, the advances whitelist keeps `new` and `employment` but not `corrected_advance`.
- **Why it matters:** the "إعداد مبلغ صحيح مرتبط بالسجل الأصلي" flow opens creation with `new=1`, `employment` and `corrected_advance`. The creation `AdvanceForm` receives `correctedAdvance={q.corrected_advance}`, and the employee-search form deliberately keeps it as a hidden field (`advances/page.tsx`, creation section).
- **What happens:** if the user re-submits the same employer during that flow, the redirect keeps `new=1` and `employment` but drops `corrected_advance`. The page then shows a normal creation form for the same employee. Saving would create an advance that is **not linked** to the corrected record, which changes the financial meaning.
- **Fix:** add `corrected_advance` (UUID) to the advances whitelist, kept only when `new==='1'`. The alternative, dropping `new` and `employment` whenever `corrected_advance` is present, loses context and is the weaker option.
- **Test:** add one normalizer case and one actual-source case: same employer with `new=1&employment=X&corrected_advance=Y` must keep all three.
