## Source matches the approved proposal
- **Readiness flag:** `subscribeToReadiness`, `clientReady` and `serverReady` are stable module-level functions (`:7-9`). `useSyncExternalStore` is used correctly (`:11`), so the server and hydration render `false`, then the client renders `true` with no mismatch.
- **Native backstop:** the outer fieldset is `disabled={!ready||busy}`, the form has `method="post"`, and `aria-busy` covers both states (`:14`). Before hydration every control is unreachable, Enter included.
- **Preparing text:** both the button and status text depend on `ready`, not on `message` state. They can't stay after hydration, and the status text includes the reload instruction.
- **`<noscript>`** sits outside the fieldset and the status paragraph, and it doesn't claim anything was saved.
- **`submit` is unchanged:** it still captures form data before disabling, converts to UTC, keeps the flight lock, uses the same authority, routes and failure/focus logic. Leaving out the `!ready` guard is correct, because the handler can't run before hydration.
