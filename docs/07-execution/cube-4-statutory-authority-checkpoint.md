Partial local implementation,2026-10-03, per Frozen Payroll section21 `statutory_rules.manage`. This closes assignment/revocation of the independent Compliance authority; it does not implement pack authoring, issuance, numeric source comparison, activation or a complete payroll financial cycle.

`can_manage_statutory_rules` defaults false on every existing/new Operator. Only a currently authorized Operator manager may explicitly assign it, including assigning it as the only task. Compliance alone grants no Operator management, tenant onboarding/lifecycle/commercial task or tenant payroll access. Current account readiness, confirmation, ban/deletion and explicit active grant remain authoritative. Revoking Operator authority clears Compliance; legacy reactivation does not resurrect it. Five-task before/after values and reasons are atomically audited. Last recoverable manager protection remains intact.

A separately named extended endpoint avoids public RPC overloads. The old seven-argument endpoint remains compatible: legacy task updates preserve existing explicitly assigned Compliance; revoke/reactivation clear it. The Arabic grant/list form includes an unchecked Compliance checkbox. Self-demotion to Compliance alone returns to the active Operator root, which acknowledges the task and clearly states that pack management is currently unavailable. No nonexistent pack action or legal readiness is implied. After authority changes, the Operator layout is revalidated so stale links disappear immediately.
