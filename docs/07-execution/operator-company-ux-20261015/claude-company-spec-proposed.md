## 2. الأساس المشترك

الأدوات الوحيدة المسموح بإضافتها، وكلها صغيرة ولغرض محدد.

### `src/lib/terms.ts`: قاموس المصطلحات
| المصطلح الحالي | البديل |
|---|---|
| علاقات التوظيف / سجلات التوظيف | الموظفون في هذا المسير |
| قنوات / وسائل / طرق تسجيل الحضور | وسائل تسجيل الحضور |
| دورة الرواتب والفترات | إعداد رواتب الجهة |
| المدخلات والإعدادات | بيانات الفترة |

- رسالة الحالة غير المعروفة الموحدة: «لم نتأكد من النتيجة. راجع الحالة قبل أي محاولة جديدة».
- المنطقة الزمنية والرموز ورقم الإصدار والمعرّفات تنتقل إلى `Disclosure` بعنوان «تفاصيل تقنية».

### `src/components/patterns/readiness-list/ReadinessList.tsx`
- فوق `StatusBadge` و`ButtonLink`.
- كل بند: `{title, state: done|todo|other-role|unknown, detail, action?: {href,label}, owner?: string}`.
- لا نسبة اكتمال.
- `unknown` يعني: «تعذر التحقق»، مع زر إعادة محاولة أو اسم الدور المسؤول.

### `src/lib/return-to.ts`
- `safeReturn(tenantId, raw)` يقبل فقط مسارات `/tenant/{tenantId}/…`، على نمط `auth/safe-next.ts`.
- يُستخدم في روابط «العودة إلى …» بين الرواتب وملف الموظف والإجازات.

### `src/components/shell/navigation-model.ts`: ترتيب صريح بدل طول الرابط
```
time:    attendance > attendance/review > leave > leave/balances > attendance/sources > leave/settings
payroll: payroll > payroll/runs > payroll/inputs > payroll/setup > payroll/advances > payroll/reports
```

**`payrollDestination`:**
- تنقل `employer` و`period` معًا، والفترة تُنقل فقط داخل `/payroll` و`/runs` و`/inputs` و`/setup`.
- إذا لم تكن الجهة صالحة لا تُنقل الفترة.

**وضع الموظف فقط (بلا مجالات فريق):**
| المدخل | الوجهة |
|---|---|
| يومي | `/me` |
| إجازاتي | `/me/leave` |
| سجلي | `/me/attendance` |

- «ملفي» يصبح رابطًا في قائمة الحساب يفتح `/me#my-employee-heading`.
- شعار الهوية يفتح `/me` لهذا الدور.

**الفريق الذي يملك خدمة ذاتية:**
- المداخل الخمسة الحالية تبقى كما هي.
- تُضاف «يومي» إلى قائمة الحساب (`workspace-navigation.tsx:111-120`).
- يُضاف كرت «حضوري اليوم» في «اليوم».
- «خدماتي» تبقى في «المزيد».

**الحفاظ على قبول الأوبيريتور:** فرع `mode === 'operator'` لا يتغير، ولقطاته المعتمدة تُعاد مقارنتها في S1.

### `T/layout.tsx`: عند فشل قراءة الهوية
- يُعرض `AppShell` بلون teal دون شعار.
- الاسم يُؤخذ من `tenant_membership_snapshot`، وإن فشل: «مساحة الشركة».
- `TenantNavigation` يعمل كالمعتاد، لأن كل رابط فيه يعتمد على قراءته المستقلة. لا تُنسب أي صلاحية.

## 3.x الرحلات الأساسية

### 3.1 التنقل والعودة
- كل صفحة فرعية تعرض `back-link` إلى أصلها المنطقي. وإن وُجد `return` صالح عبر `safeReturn`، يُستخدم هو.

- **الرصيد الحالي:** من `leave_my_balances` (أو `leave_hr_balances` للموارد البشرية)، مُفلترًا بالنوع.

  - إذا لم يوجد حساب: «لا يوجد رصيد مسجل لهذا النوع».
  - إذا فشلت القراءة: «تعذر التحقق من الرصيد».

**بعد B2: «أثر الطلب»:**
- يُستدعى عند اكتمال (النوع، التاريخين، نصف اليوم، الجزء)، عبر server action.
- كل استدعاء يحمل رقمًا تسلسليًا، وتُتجاهل كل استجابة لا يطابق توقيعها المدخلات الحالية.

| الحالة | العرض |
|---|---|
| جاري الحساب | «يُحسب الأثر…» |
| `ready` | «يُحتسب {total} يوم» |
| `ready` مع رصيد متابَع | «المتاح الآن {available} يوم؛ بعد الاعتماد يبقى {after} يوم» |

| `unavailable` | سبب نصي، مع إبقاء الإرسال ممكنًا. **المحاسبة النهائية تتم عند الإرسال** |

- **تنبيه ثابت:** «الطلبات المعلّقة الأخرى لا تحجز رصيدًا».
- **الإرسال يبقى كما هو.** صفحة التفاصيل بعد الإرسال هي المرجع. إذا اختلف المحسوب عند الإرسال عما عُرض: «احتُسب الطلب عند الإرسال: {n} يوم».
