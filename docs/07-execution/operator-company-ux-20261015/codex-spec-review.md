Accepted direction: complete Operator coverage, company context, permission-aware list reuse without a new listing RPC, task-based team controls, explicit lifecycle/legal review, independent capability/visual/journey gates and bounded implementation batches. No new audit read permission, invented administrator email or fabricated activity counters.

Material clarifications before freezing:

1. Preserve the existing finite-denial capability in an advanced duration editor. Proposed D-05 removes its only interface, contrary to the owner's full functional coverage requirement. The ordinary switch remains one action; advanced controls must not complicate that path.
2. Specify how an existing finite grant's deadline survives an ordinary OFF then ON. An indefinite denial followed by indefinite first grant would silently erase the original end date. Never default an existing finite allocation to unlimited. Define authoritative state/history needed, exact expiry preservation, and renewal after expiry; no browser-side guess.
3. No new attempt table is necessary if the UI honestly reports authoritative current state instead of attribution to the original request. However `unchanged` includes the complete requested plan and durations, runs only after authorization/tenant/conflict checks, and is not a success claim about a particular attempt. A lost response triggers re-read and explicit fresh user intent; never automatic mutation replay. Verify all finally affected dependencies and expected states before any atomic write. A revised plan requires renewed consent.
4. Authority collection must retain explicit active-operator gating and fail closed per failed permission; avoid repeating all RPCs independently for every component. Use request-local caching only, with no cross-user cache. Final RPC explicitly revokes PUBLIC/anon/service_role execute before granting authenticated.
5. Use one comparable baseline/completion run per representative journey for deterministic action/input counts. Repeat timing measurements only when a specific performance question warrants them. Three rounds for every path/viewport do not add useful evidence to this scope. UI-only batches do not rerun financial database suites.
6. End-date serialization must preserve the authoritative deadline exactly; display Cairo's inclusive last day without an off-by-one conversion. Changing a duration remains an explicit user choice. Check legacy reason provenance before asserting every historic reason was user-entered; preserve history without fabricating authorship.

No product code changed by this checkpoint. Full Operator implementation/acceptance and the entire subsequent company phase remain open. Docker permanent repair is a prerequisite for runtime qualification; a source/build pass never substitutes for it.
