# S4 implementation decision: first saved branding

D9 allows a visible editable suggested reason only for the initial low-impact branding setup. Inspection of the existing tenant_branding_snapshot showed that its default-looking name/color/logo values cannot establish whether a row has already been saved. A user can deliberately save the defaults. Inferring first use from those values would violate D9.

The narrow implementation adds has_saved_branding to that same authorized read snapshot using b.tenant_id IS NOT NULL. It adds no endpoint, permission, table access, mutation or aggregate. The exact-once pg_get_functiondef anchor preserves the existing function and grants. The UI suggests a reason only on an explicit false; an older/unknown response keeps the reason empty. This small read-contract addition is recorded for final independent Company review; it is separate from the conditional attendance B3 and does not broaden that contract.

Entity/site creation gets visible editable suggested reasons. Existing update/default/deactivate/reactivate forms retain empty required reasons, server validation and the same RPCs. Actions move into the shared accessible Sheet. The at-capacity detail page explains the limit instead of offering an unusable Add link, retaining the existing authoritative creation-page and database limits.
