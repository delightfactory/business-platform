## Graph conclusions and unresolved edges

Observed compatible principal edges include E → H → B → Leave configuration → R → W → balance/account; classification uses H → W. Time W writers read Leave context **without** acquiring Leave locks below W. A Payroll path that locks W then R/C/T would create the inverse of Leave's R/C/T → W path and is prohibited pending a compatible reviewed protocol. Period serialization cannot be placed before/after Employment merely by convention: existing source writers currently do not participate in a Payroll period lock.

Mixed order requiring investigation: override cancellation O → H versus override assignment H → INSERT new O. The latter inserts a different row, so this is **not a demonstrated same-row inversion or proven deadlock**. FK/exclusion/index locking and actual competing fixture must determine risk. Likewise multi-H ordering varies (Leave UUID, Time open-day employee-code/Employee, importer start-date/id); Payroll's proposed UUID sorting alone is not proof against batch inversions. Current source review has not qualified these races.

Advisory edges differ by key: Tenant authority hash(Tenant,90427), People catalog hash(Tenant,0), Leave balance hash(Tenant+Employee,90429), Leave config scoped keys and operation keys, Time classification187904. Equal salt does not mean equal advisory resource; string concatenation and resource scope must be preserved. Triggers/DML and security authority mutation paths can add edges; no global graph closure is claimed.

G3 still needs Payroll-aware People guards and correction routing; existing manual warning/materialized Time/Leave end checks do not satisfy it. G4 still needs locked current manifest reconstruction detecting new approved rows, successors/cancellations and affected source sets; locking only already-previewed rows misses insertion phantoms. Narrow source-consumption permission and effective policy/config revalidation remain D05. No projection flag or preview hash establishes consumption.
