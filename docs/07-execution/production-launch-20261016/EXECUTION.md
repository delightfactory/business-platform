## ما نُفذ وتحقق

- بدأ المشروع بلا مستخدمين أو شركات أو ملفات أو schemas للتطبيق. طُبقت 213 مهاجرة أصلية ثم مهاجرة التشغيل؛ تطابقت قائمة الإصدارات المحلية والسحابية: 214/214. البصمات في `applied-migrations.json`، والحصر الأصلي محفوظ في `migration-manifest.json`.
- bucket `tenant-branding` خاص، وحده 2 MiB. لم تُنقل بيانات QA أو قواعد رواتب مصطنعة إلى الإنتاج.
- وظيفة حذف أدلة الموقع المنتهية مجدولة كل خمس دقائق بهوية postgres؛ سُجل تشغيل ناجح بتاريخ `2026-10-15T22:40:00Z`. سجل المهمتين المملوكتين يحتفظ بـ30 يومًا. لا حذف لسجلات الحضور.
- تفعيل RLS لجدول readiness الخاص أغلق الاستثناء البنيوي الوحيد: صفر جداول تطبيق دون RLS، وصفر SECURITY DEFINER بلا search_path فارغ. لا تغيير لمنح وظائف الصيانة إلى أدوار التطبيق.
- حساب المدير الذي حدده المالك أُنشئ بكلمة أولية عشوائية غير مُسلّمة، ثم استُخدمت وظيفة bootstrap الأصلية: مدير فعال واحد. لم ينشأ حساب عميل أو شركة تجريبية. لا توجد ترقية عبر user_metadata.
- التسجيل العام والمجهول معطلان، وتأكيد البريد مفعل، وحد كلمة المرور ثمانية أحرف. تحقق مستقل من `/auth/v1/settings` أكد تعطيل التسجيل العام والمجهول وتفعيل مزود البريد.
- Site URL يطابق نطاق المنصة، وقائمة العودة أربعة مسارات فقط على النطاق نفسه؛ معاملات سياق الدعوات مسموحة على مساراتها دون wildcard للنطاقات.
- أربعة متغيرات على Vercel Production فقط. المفتاح العام publishable؛ الاعتماد السري للخادم محفوظ في `SUPABASE_SECRET_KEY` فقط. استُخدم اعتماد service_role المتاح للإدارة من CLI بعد اكتشاف أن عرض المفتاح secret الحديث مقنّع؛ لم يُستخدم النص المقنّع كاعتماد نهائي، ولم تُطبع الأسرار. لا مفاتيح إنتاج في Preview أو ملفات المتصفح العامة.
- Resend يستخدم نطاق `delight-world.com` الموثق ومفتاحًا جديدًا للإرسال فقط ومحصورًا بهذا النطاق. أُلغي مفتاح أولي غير مستخدم ضمن الإعداد، وبقي المفتاح النهائي المخصص. إعدادات Protection Giants لم تتغير.
- SMTP محفوظ على `smtp.resend.com:465`. وصلت رسالة الاستعادة إلى البريد الذي حدده المالك؛ Resend سجّل delivered. الرابط عاد إلى `/auth/password/update` على النطاق الصحيح في نفس جلسة Edge، وظهرت شاشة اختيار كلمة المرور. اختيار كلمة المرور والدخول الفعلي التالي متروكان للمالك؛ لا نسجلها في تقرير.
- فحص رسالة الإرسال كشف بقايا النص الافتراضي بجانب العربية. أُعيد استبدال محتوى محررات القوالب بالكامل. إعادة تحميل صفحة قالب الاستعادة أثبتت أن المحتوى المحفوظ عربي فقط؛ وتصحيح invite وmagic_link أزال النص الافتراضي مع حفظ token_hash وسياق الدعوة. آخر رسالة فُحصت ما زالت تعرض المحتوى السابق المزدوج؛ لا تُعد إثباتًا لوصول النسخة النهائية من النص، ويحتاج الإرسال اللاحق إلى تأكيد. رابط إعداد الحساب نفسه نجح.

## النسخ والاسترجاع وما بقي

نجح تصدير أولي محلي خارج OneDrive: schema بحجم 2,165,092 بايت، وdata بحجم 28,186 بايت مع بصمات خاصة. بيانات Auth ضمن التصدير؛ لا توجد ملفات Storage للنسخ وقت البداية. هذه ملفات محمية خارج Git وليست نسخًا دورية أو إثبات استرجاع. pg_dump أبلغ عن علاقات دورية في data-only؛ يجب مراعاة ترتيب الاسترجاع وتعطيل triggers في جلسة صيانة معزولة عند الحاجة، لا في قاعدة الإنتاج القائمة.

المؤسسة كانت Free وقت الإعداد، ولا نسخ يومية مُدارة مفعلة. أُرسل سؤال للمالك بشأن ترقية Pro أو إبقاء الاختبار مؤقتًا؛ لم نشتر اشتراكًا. يلزم تثبيت خطة النسخ الدوري واسترجاع معزول ونسخ محتوى Storage قبل الاعتماد على بيانات الشركات. التفاصيل: [حدود نسخ Supabase](https://supabase.com/docs/guides/platform/backups).

المتبقي: حفظ المالك كلمة مروره والدخول بها؛ تأكيد نص البريد النهائي بإرسال لاحق؛ تأهيل رحلة الشركة المقصودة ودعواتها بعد تحديد بياناتها؛ واختبار الهاتف الفعلي قبل الاعتماد على التقاط الموقع. تأهيل الرواتب بالقواعد الرسمية والمطابقة المالية لم يُغلق بمجرد النشر.

## التخزين والاستمرار

المصدر والتشغيل والنسخ والمخرجات في run خارجي عن OneDrive. إعدادات CLI المؤقتة لم تُنسخ إلى إعداد التطبيق المحلي. أبقينا بيئة QA التي يستخدمها المالك ونسخها الخاصة دون حذف أو reset. صورة postgres 17.11 المستخدمة للتصدير نحو368MB؛ تُحتفظ أثناء استكمال النسخ والاسترجاع، ولا يُمسح كاش Docker العام. تحفظ السجلات المختصرة والبصمات، ولا تُرفع ملفات النسخ أو الأسرار إلى Git.
