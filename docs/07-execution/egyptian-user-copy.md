# لغة الواجهة في بيئة العمل المصرية

حُصرت النصوص العربية الثابتة، ومعها النصوص الإنجليزية الظاهرة مباشرة في JSX وعناصر الوصول، من 528 ملف مصدر ودعم: 7,482 موضعًا نصيًا، منها 7,237 داخل التطبيق. تشمل العناوين والأزرار والحقول والإرشادات ورسائل الأخطاء والحالات والتصدير ونصوص الوصول. بعض المواضع مفاتيح تنسيق أو أجزاء جملة وليست رسائل مستقلة؛ لا يعني هذا العدد عدد شاشات أو مراجعة بيانات كل سجل فعلي.

عُدّل 408 مواضع في 84 ملف مصدر. الحصر التفصيلي المحلي `user-copy-inventory.csv` يحتوي المسار والسطر والصياغة قبل وبعد وحالة التعديل؛ `user-copy-changes.csv` يقتصر على التغييرات. أُبقيا خارج Git لتجنب إضافة آلاف صفوف الأدلة للمستودع. المرجع المستمر للتنفيذ هو هذا القاموس والكود نفسه.

«الموارد البشرية» تسمية مألوفة أُبقيت. لا تُستبدل الكلمات داخل أسماء الحقول أو الأكواد أو قواعد استيراد CSV أو شروط المطابقة. حساب مبدئي، اعتماد، حفظ نهائي وصرف حالات مختلفة؛ الحفظ لا يعني الدفع. التصحيح المقابل يحفظ القيد الأصلي، وبيانات العمل لا تعني مأمورية. تغيير النص لا يمنح صلاحية ولا يغير حساب الأجر أو الضريبة أو التأمينات أو رصيد الإجازة.

المصطلحات المالية تستأنس بالتسمية لدى [مصلحة الضرائب المصرية](https://www.eta.gov.eg/ar/news/mnzwmt-twhyd-ass-wmayyr-ahtsab-drybt-alajwrwalmrtbat) و[الهيئة القومية للتأمين الاجتماعي](https://www.nosi.gov.eg/ar/Pages/HomePage/Home.aspx). القاموس معيار تحرير للواجهة، وليس اعتمادًا حكوميًا للمنصة أو مراجعة قانونية لنسب الحساب.

مراجعة Claude Opus 5.5 Medium كشفت أخطاء تطابق لغوي وغموض الحركة المقابلة للخصم؛ عولجت في المصدر. فحص بنية المصدر أثبت أن الفروق نصوص عرض فقط، دون تغيير الشروط أو مفاتيح المطابقة أو الطلبات. نجح ESLint وTypeScript والبناء المجمع؛ لم تُكرر اختبارات قاعدة البيانات أو جولات التصوير.

حدود الحصر: 173 موضعًا من مهاجرات قاعدة البيانات، و65 موضع تطوير، وبيانات الموظفين والشركات والمدخلات والأسباب الواردة وقت التشغيل لا تُعاد كتابتها هنا. بقيت المهاجرات التاريخية والبيانات كما هي؛ الحصر يصنفها منفصلة. قبول الحالات المالية واختبار الجهاز الفعلي يظلان كما في [حالة الموارد البشرية](hr-ui-readiness.md).
